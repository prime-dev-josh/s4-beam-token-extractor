Crash event search

Ways to search

  • One day of crashes. Crash date, single day, such as 2026-01-01.
  • A span of crash dates. Crash date range, sent as 2025-12-01~2025-12-31.
  • Records touched at one moment. Update time, single timestamp, such as 2026-08-01T00:00:00.
  • Records touched during a window. Update time range, such as 2026-07-15T00:00:00~2026-07-15T23:59:59.
  • Crashes in one period that changed in another. Set both filters. Example: crashes in January 2026 and updates in March 2026.
  • How many records match. Totals load automatically once a date filter is complete. Page is left off that request.
  • A range of Signal4 Beam pages. Each API page holds 500 records. Search fetches every page in the from–to range.

Read-only search of /crash-event/v1/search. At least one date filter is required. Results stay in this window and are not written to disk.

Crash date

When the crash occurred. YYYY-MM-DD, through today. A range joins the days with ~.

Update time

When Signal4 Beam last updated the record. YYYY-MM-DDTHH:mm:ss, through now. A range joins the timestamps with ~.

This search uses only the update time, so Signal4 Beam scans the full table and the response can be slow. Narrow the window, or add a crash date range.

Add a crash date, an update time, or both to load match totals.

Signal4 Beam returns 500 records per page. Search fetches every page in this inclusive range. Results paging on the table tab is separate and local.

Local paging only changes what you see. CSV and PDF still export every fetched record in the columns currently shown.
